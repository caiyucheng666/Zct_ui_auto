# 职策佳平台 UI 自动化测试框架

针对「浙江深佳科技」职策佳平台（https://zct.aisjkj.com/）的 UI 自动化测试项目，
基于 **Python + Pytest + Selenium + POM + YAML 数据驱动 + Allure** 搭建。

> 平台特点：同一账号同时绑定**个人身份**与**企业身份**，登录后需二次选择身份进入不同工作台。
> 本项目正是围绕「登录 + 双身份切换」这一核心场景展开。

---

## 一、技术栈

| 模块 | 技术 |
| --- | --- |
| 语言 | Python 3.11 |
| 测试框架 | Pytest（参数化、fixture、标记） |
| UI 自动化 | Selenium WebDriver |
| 设计模式 | POM（Page Object Model）页面对象模型 |
| 数据驱动 | YAML（数据与代码分离） |
| 报告 | Allure（含步骤、截图、日志） |

## 三、分层设计（POM）

```
测试用例层 (tests/)  ──调用──▶  页面对象层 (commons/*_page.py)  ──继承──▶  基础层 (commons/base_page.py)
     │                                │
     │ 只关心"做什么"                  │ 关心"怎么做"（封装元素定位与交互）
     ▼                                ▼
  YAML 数据驱动 (data/)             Selenium WebDriver
```

- **测试用例层**：只描述业务步骤与断言，不写定位代码。
- **页面对象层**：每个页面一个类，封装该页面的元素定位与交互细节，页面变化只改这一层。
- **基础层**：`BasePage` 提供统一的显式等待、点击、输入、文本断言等通用能力。
- **数据驱动**：用例数据集中在 `data/*.yaml`，通过 `@pytest.mark.parametrize` 注入，新增用例只改数据不改代码。

## 四、环境准备

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 确保 chromedriver.exe 与本地 Chrome 大版本一致
#    （Windows 可在 帮助 → 关于 Google Chrome 查看版本）
#    本项目自带 chromedriver 151.0.7922.71，适配 Chrome 151.x

# 3. 安装 Allure 命令行工具（用于生成报告）
#    https://github.com/allure-framework/allure2/releases
```

## 五、运行方式

```bash
# 方式一：一键运行全部用例并生成 Allure 报告
python run.py

# 方式二：运行指定模块 / 用例
pytest tests/test_login.py
pytest tests/test_login.py::TestLogin::test_login_success
pytest -m personal      # 只跑个人身份用例（-m 标记）
pytest -m work_creation # 只跑企业工作创作用例（-m 标记）

# 方式三：查看 Allure 报告（生成后）
allure open ./reports
```

## 七、关键实现说明

1. **登录入口的 SPA 渲染等待**：Vue 单页应用在 `driver.get()` 返回后才异步渲染，
   登录按钮"可见"不等于"可点击"（点击事件尚未绑定），因此在点击前增加短暂等待。
2. **toast 提示的健壮抓取**：页面存在多个 `role="alert"` 元素（含隐藏空占位），
   采用轮询所有 alert、返回第一个有文本的方式，而非死等第一个可见元素。
3. **身份断言**：个人身份以 `URL 含 siteMode=c` + `职业评测` 文案判定；企业身份以
   `我的企业协作入口` + `企业工作创作` 导航判定，两者特征互斥、区分清晰。
4. **工作创作入口**：企业身份首页顶部导航「企业工作创作」进入 `/company/enterprise/WorkCreation`，
   页面以 `h3` 卡片列出 8 个功能入口，点击后跳转到各自路由（如 `policyElucidation`、
   `technical`、`claims`、`patent`、`similarPatents` 等）。
5. **空表单校验**：工作创作各功能的提交按钮在空表单时**不**禁用，点击后才以 `role=alert`
   的 toast 提示（如「表单验证失败」「请选择文件」「请完善表单信息」），故校验用例
   断言的是"出现 alert 提示"而非按钮禁用态。
6. **完整生成流程**：填写表单 → 提交 → 等待 AI 生成完成 → 断言结果内容。
   生成完成的判定为「无"生成中"（连续两次，处理多阶段生成闪烁）+ 结果内容已渲染」，
   各功能的结果断言关键字不同（技术交底书=「核心技术创新点」、权利要求书=「本步已完成」、
   专利说明书=「背景技术」、相似专利=「专利申请号」、政策解读=「一句话解读」、
   项目方向挖掘=「文件抽取解析结果」）。
7. **原生 date 输入的填写**：Chrome 的 `<input type=date>` 在 zh-CN 下无法用 `send_keys`
   直接填 ISO 字符串（会得到空值或错乱日期），需点击后分段输入「年 → 方向键 → 月 →
   方向键 → 日」。
8. **政策解读无提交按钮**：选择政策文件（点击搜索框展开文件列表并选中）后页面自动跳转到
   解读结果页，无需再点提交。
9. **项目申报三功能是向导流程**：项目方向挖掘 → 立项报告 → 项目方案 是同一「项目工具链」
   里的三步（1/2/3），前文生成结果可供后文「历史项目参考」使用。三者均**必须提供参考文件**
   （上传本地文件 或 导入知识库文件），项目方向挖掘还需选择「项目级别」下拉框。其中立项报告
   本身还有内层多步向导（项目基本信息 → 项目概述 → 项目立项），用 `fill.step2` 填第二步。
10. **登录身份**：工作创作在个人身份与企业身份下都可用，本套用例使用**个人身份登录**
    （个人账号职策点充足），功能路由相同仅 `siteMode` 参数不同（个人 `c` / 企业 `b`）。
11. **表单持久化草稿**：项目方向挖掘等表单会把上次填写内容保存为服务端草稿（异步加载）。
    若草稿已有值，直接用草稿值即可（覆盖草稿会触发 Vue 响应式问题导致提交静默失败）。
    因此项目方向挖掘的 `fill` 仅 `import_kb_file`（其余字段用草稿值），而立项报告/项目方案
    字段为空、需在 `fill` 里显式填写。
12. **完整生成用例的运行策略**：完整生成会消耗职策点，故 8 个完整生成用例默认标记 `skip`
    不重复跑。需要真正验证生成流程时，临时移除对应功能 YAML 里的 `skip_reason` 再运行。
13. **知识库页结构（实测校准）**：根页是**文件夹卡片网格**（h3 为文件夹名，含更多菜单）；
    点文件夹卡片进入**文件卡片网格**（h3 为文件名，含处理中/处理完成徽标、图谱状态、引用次数）。
    上传成功后文件默认归入「未分类」，故上传类用例先打开该文件夹再断言文件卡片。
14. **知识库上传流程**：点「上传」打开「个人文件上传」弹窗，隐藏的 `input[type=file]`
    随弹窗渲染（非弹窗时不存在），用 `send_keys` 写本地路径选文件，再点「完成」真正上传
    （成功 toast「成功上传 N 个文件」，弹窗约 6s 内关闭）。选择文件瞬间前端即校验并弹
    `role=alert` toast：不支持类型（exe/zip/txt）提示「格式不支持…」且完成按钮置灰；
    >20MB 提示「超过20MB限制，已跳过」（toast 约 2~3 秒后消失，需在选文件后的短窗口内
    捕获，`select_file` 已内置 3 秒轮询返回提示文本）；0 字节空文件平台**不拦截**。
    弹窗关闭动画期间其黑色遮罩（`data-state="closed"`、`pointer-events: auto`）会短暂
    拦截点击，打开文件夹用 JS 强制点击绕过。另因 SPA 异步重渲染，「上传」按钮普通点击
    偶发 stale 引用异常，`open_upload` 以「隐藏 file input 是否已进入 DOM」判定弹窗
    是否打开，未打开且点击失败时自动重试（打开后即返回、不再二次点击避免误关弹窗）。
15. **知识库删除**：文件卡片右上角更多按钮 → 下拉菜单「删除」→ 触发**浏览器原生 alert**
    （「确定要删除该知识文件吗？此操作不可恢复。」），需 `EC.alert_is_present()` +
    `driver.switch_to.alert.accept()` 处理，无 DOM 内确认按钮。更多按钮用 JS 点击绕过
    残留遮罩；卡片仍显示「处理中」时先等待（处理中文件删除可能被平台推迟），
    处理完成 / 处理失败的文件均可直接删除；同名卡片存在多个（历史失败运行残留）时
    循环删除直至清空。
16. **知识库搜索**：根页搜索框提示「搜索文件夹…」，按关键字过滤文件夹卡片，无结果文案
    「未找到匹配的文件夹」；进入文件夹后搜索框提示「搜索知识…」，过滤文件卡片。
    **注意**：平台搜索索引仅收录已处理（图谱完成）的文件，新上传文件处理完成前搜不到，
    故搜索命中用例用稳定存在的文件夹名做断言（不依赖新上传文件）。
17. **样例文件自动生成**：知识库用例所需 PDF/DOC/DOCX/PPT/PPTX 等样例文件在测试模块导入时
    自动生成到 `temps/test_files/`（gitignore），合法 OOXML/PDF 结构 + OLE2 magic 头；
    PDF 样例必须含字体资源与文本流（否则平台服务端解析不出文字会标记「处理失败」，
    处理失败的文件不会被删除流程清理）；上传的临时文件用后删除，保持线上知识库干净。
18. **SPA 点击健壮性**：站点为 SPA，部分元素会短暂重渲染或被角标/遮罩遮挡，普通
    Selenium click 偶发 stale / 被拦截，处理如下：顶部导航「知识库」按钮会被橙色角标
    拦截（进入用 JS 点击）；「上传」按钮点击瞬间可能 stale（`open_upload` 按隐藏
    file input 是否进入 DOM 判定弹窗是否已打开，未打开且点击失败时自动重试）；
    「完成」按钮选文件后偶发重渲染（`click_done` 按秒轮询可点击，弹窗已关闭则视为
    已提交）；上传校验 toast 读取瞬间可能被替换（`select_file` 跳过 stale 元素）；
    文件卡片更多按钮的下拉菜单由 reka-ui 在 pointerdown 触发，仅 JS .click() 偶发
    打不开（`_open_more_menu` 派发完整指针/鼠标事件序列，菜单未弹出时回退真实点击）；
    登录入口按钮偶发被拦截导致登录弹窗未打开（`LoginPage.open` 以手机号输入框是否
    出现判定，未出现则重试点击）。
